## Task 1 — `.github/workflows/release.yml`

### Manual trigger

Added `workflow_dispatch` with a required `tag` input:

```yaml
on:
  push:
    tags: ["v*"]
  workflow_dispatch:
    inputs:
      tag:
        description: "Tag to build and publish (e.g. v0.6.0). Create/push the tag first."
        required: true
        type: string
```

The tag input is required so a manual run cannot accidentally publish a release
named after the selected branch. `tagName` / `releaseName` use:

```yaml
tagName: ${{ inputs.tag || github.ref_name }}
```

so tag pushes keep working unchanged.

### Permissions & uploads

- `permissions: contents: write` is present at the workflow level (required to
  create the Release).
- `tauri-apps/tauri-action@v0` runs the Tauri build and uploads:
  - `TaskFlow_<version>_x64_en-US.msi` (WiX),
  - `TaskFlow_<version>_x64-setup.exe` (NSIS),
  - their `.sig` files,
  - `latest.json`.
- `includeUpdaterJson: true` and `updaterJsonPreferNsis: true` make the updater
  consume the NSIS installer; `args: --target x86_64-pc-windows-msvc` pins the
  Windows target.
- Signing secrets are wired through `TAURI_SIGNING_PRIVATE_KEY` /
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`; `GITHUB_TOKEN` creates the release.

## Task 2 — `docs/RELEASE_PROCESS.md`

Added the exact manual steps:

1. **Repository must be PUBLIC** — anonymous updater downloads of release
   assets fail on private repos (404/401).
2. **GitHub Secrets** — `TAURI_SIGNING_PRIVATE_KEY` and
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
3. **Manual trigger** — Actions → **Release** → **Run workflow**, choose the
   branch and enter the existing tag.
4. **Manual release fallback** — build locally with `npm run tauri build`,
   assemble `latest.json` from the NSIS `.exe` + `.sig`, create a release for the
   tag and attach the MSI, EXE, both `.sig` files and `latest.json`; publish it
   as the latest non-prerelease.
5. Expanded troubleshooting (workflow not running, private repo/404, signature
   mismatch).

## Known limitations / follow-ups

- The workflow builds Windows artifacts only; macOS/Linux jobs are out of scope.
- A manually typed tag must already exist; otherwise GitHub may create it at the
  default branch head.
- The private repository caveat remains fundamental: for a private repo, host the
  artifacts + `latest.json` on a public static host (or proxy) and update the
  endpoint.
- `latest.json` generated by hand must use the exact `.sig` contents and a URL
  that is publicly downloadable.
